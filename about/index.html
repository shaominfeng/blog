为什么写

2022 年 11 月 ChatGPT 发布时，大多数人看到的是「会聊天的 AI」；三年后，AI 已经在写代码、跑流程、做研究， 甚至开始以「数字同事」的身份进入工作流。变化太快，讨论很容易变成参数对比和产品站队。

这个文章集想做的，是把技术放回它出现的那一刻：它当时解决了什么具体问题？为什么是这个方案？ 代价是什么？下一个瓶颈又在哪里？当这些线索连起来，趋势就不再是新闻标题，而是一条可以理解的因果链。

怎么写

  • 时间线为骨架。以官方发布、论文与产品更新为锚点，先确认「什么时候发生了什么」。
  • 问题为线索。每一项技术都回答「它替代了什么旧方案，又制造了什么新问题」。
  • 多角色视角。同一项技术，对用户、应用开发者、产品经理和模型开发者的重要性并不相同。
  • 实践校验。用企业平台的真实落地记录，检查哪些判断只在 PPT 里成立。

观察窗口与边界

目前的主线《从对话到协作》以 Claude / Anthropic 生态为主要观察窗口，原因是团队在日常开发中使用 Claude Code 最深， 对 Agent 编程的体感最完整；同时覆盖 OpenAI（GPT-5、Codex）、Google（Gemini 3）与 DeepSeek（R1）的关键进展。 这意味着部分章节的深度并不对称，读者应结合自己的工具栈对照阅读。

企业实践章节涉及内部平台，已隐去公司名称、产品名称与具体金额，只保留可迁移的方法与里程碑。 所有观点为个人观察，不代表任职机构。若发现事实错误，欢迎通过邮件指出。
