## 引言

如果说2022年之前的AI还是"实验室里的玩具"，那么从2022年11月开始，我们见证了AI从学术走向实用的历史性转折。短短三年间，AI不仅学会了对话、写代码、画图，更发展出了推理能力、长文本理解和自主行动能力。

本文采用**时间线叙事**的结构，将AI发展的关键事件与技术演进深度融合，让读者理解"为什么出现X技术，X解决了什么问题，遇到什么新挑战，如何继续演进"的完整脉络。

> **关于视角说明**：本文以 **Claude/Anthropic 生态为主要观察窗口**。原因很实际——我们团队日常使用 GitHub Copilot（公司提供的非满血版本，能力受限较多）。在 Agent 编程领域，Claude Code 和 OpenAI Codex 同属第一梯队（Claude Code 在推理密集型任务和交互式开发上更强，Codex 在 Token 效率和沙箱并行执行上领先），我们选择了 Claude Code 作为主力工具，因此积累了最深的实践体感。文中也涵盖了 OpenAI（GPT-5、Codex）、Google（Gemini 3）、DeepSeek（R1）等重要进展，但深度不及 Claude 生态部分，读者可结合自身工具栈做对照阅读。

## 🍽️ 理解AI系统：餐厅类比

> 💡 在深入技术前，用一个日常场景帮你快速建立AI系统的完整心智模型。

### AI系统的完整架构

想象AI系统就像一个智能餐厅，完整的运作涉及多个层次：

![餐厅架构图](/blog/images/restaurant-architecture.webp)

*图：AI系统的4层餐厅架构 - 顾客、服务团队（推理层⭐核心）、后厨、工具层*

**核心映射表**：

| 餐厅角色 | AI技术 | 核心作用 |
|---------|--------|----------|
| 👤 **顾客** | 用户 | 提出需求（从详细描述→简单说目标）|
| 🎯 **领班+服务团队** | **推理层** | 理解需求、规划、协调、优化成本 ⭐ |
| 👨‍🍳 **主厨** | AI模型 | 核心能力（GPT-4, Claude Opus）|
| 🔥 **炉灶** | GPU | 算力资源（火力越大越快）|
| 📚 **菜谱宝典** | Skills | 知识、方法论（怎么做菜）|
| 🛒 **采购系统** | MCP | 获取外部资源（买食材）|
| 🔪 **基础厨具** | Function Calling | 基础工具（刀、锅、铲）|
| 🪑 **餐桌大小** | 上下文窗口 | 主厨记忆力（4K→2M）|

**关键洞察**：
```
很多人以为：AI = 主厨（模型）
实际上：AI系统 = 主厨 + 服务团队（推理层）+ 工具

推理层（服务团队）才是核心差异：
- 同样的主厨（Claude Opus），不同的服务团队
- Anthropic的服务团队（Claude Code）更懂优化、成本控制、流程管理
- 这就是"推理层才是进化引擎"的意思
```

### 前置突破：RLHF——让厨师听懂顾客的培训课程

```
2022年之前（GPT-3时代）：
厨师手艺很好，但只会做自己想做的菜，经常答非所问
→ 有能力，但不听话

2022年（RLHF突破）：
给厨师上了一门"客户服务培训课"——
让真人顾客评价菜品，厨师根据评价不断改进
→ 培训后的小厨师（1.3B），顾客满意度居然超过了大厨师（175B）！
→ 这就是ChatGPT能火的根本原因：不是厨艺更好，而是终于听懂人话了
```

### 点菜方式的演进（核心变化）

```
2022年（Prompt工程萌芽）：
顾客必须是烹饪专家
"鸡肉切1cm见方，腌制15分钟，加生抽、料酒、淀粉；
 花生提前炸脆；干辣椒剪段；糖醋比例1:2..."
→ 门槛太高！

2023年（Prompt工程黄金时代）：
顾客需要懂术语
"宫保鸡丁，按川菜传统做法，微辣，花生脆"
→ 部分岗位年薪高达$20万的点菜顾问（Prompt工程师）

2024年（模型变聪明）：
顾客简化描述
"来个宫保鸡丁，微辣，花生多一点"
→ 厨师能理解意图了

2025年（Agent诞生）：
顾客说目标
"给我一桌川菜宴席，8人，预算2000"
→ 领班自主规划全流程

2026年（协作时代）：
顾客说需求
"办个200人婚宴，中西结合"
→ 多个领班协作完成
```

### MCP vs Skills：食材 vs 菜谱

**核心区别**：
```
MCP（采购系统）= "我能拿到什么食材"（能力层）
- 菜市场接口、海鲜供应商、调料仓库
- 提供：外部资源、实时数据
- 特点：Token消耗大、有安全风险

Skills（菜谱宝典）= "我知道怎么做菜"（知识层）
- 《川菜大全》《法式甜点》《烹饪技巧》
- 提供：方法论、最佳实践、标准流程
- 特点：Token省98%、安全、可复用

Function Calling（基础厨具）= "我有刀锅铲"（工具层）
- 最基础的工具调用能力
```

**三种组合场景**：
```
1️⃣ 只有MCP，没有Skills：
   有顶级食材（龙虾、松露）但不会做 → 浪费

2️⃣ 只有Skills，没有MCP：
   会做法餐但拿不到食材 → 暂时做不了

3️⃣ MCP + Skills：
   会做菜 + 能采购 → 完美 ✅
```

**为什么Skills在日常开发中更常用？（基于笔者实际使用估算）**
```
约100个日常开发任务统计（笔者个人经验）：
- ~80个：只需Skills（食材餐厅有，如code review）
- ~15个：需要Skills+MCP（如分析GitHub趋势）
- ~5个：只需MCP（如简单数据获取）

→ Skills在~95%的日常开发场景中发挥作用，是基础设施
→ MCP在~20%场景需要，是重要补充
注：此统计基于作者个人AI编程场景，不同使用场景比例可能不同
```

### Agent自主性：从服务员到领班

```
服务员（传统AI）：
顾客："上菜"
服务员："上哪道菜？"
顾客："宫保鸡丁"
服务员："好的" [只执行这一个指令]

领班（Agent AI）：
顾客："给我一桌川菜宴席，8人，预算2000"
领班：[自主执行]
  1. 查菜谱定菜单
  2. 去采购拿食材
  3. 协调后厨按顺序做
  4. 质量检查、动态调整
  5. 控制上菜节奏
  → 报告："已全部上齐，请慢用"

关键：从"每步确认"到"说目标就行"
```

### 性能优化：餐厅经营的艺术

```
💰 成本优化：
✅ 提前备菜（Prompt Caching）→ 葱姜蒜提前切好，快7倍
✅ 收空盘子（Auto-Compact）→ 餐桌腾出空间，省75%租金
✅ 选择性携带菜谱（Skills）→ 只给需要的书，省98% Token

⚡ 速度优化：
✅ 备菜缓存 → 延迟降85%
✅ 智能索引（RAG）→ 1000本书快速查到相关章节
✅ 多炉灶并行（并行GPU）→ 多道菜同时做

→ 不是单一技术，是组合优化
```

### 什么是Agent AI？

**简单定义**：能够**自主行动**的AI，不需要每步都指挥。

**核心区别**：

```
普通AI（工具）：
用户: "部署功能"
AI: "要执行什么命令？"
用户: "先跑测试"
AI: [运行] "失败了"
用户: "帮我修"
AI: [修复] "修好了"
用户: "再测试"
...
→ 每步都要你指挥，像"遥控玩具"

Agent AI（助手）：
用户: "部署功能"
AI: [自主执行]
  1. 读部署文档
  2. 跑测试 → 发现失败
  3. 分析原因 → 修复
  4. 再测试 → 通过
  5. 构建 → 部署
  6. 验证 → 通知
→ 报告："已完成部署"

→ 只需要一句话，像"委派给同事"
```

## 同一技术，不同视角：谁在用，怎么用？

> 💡 前面我们说"Prompt工程在弱化"、"MCP有安全问题"、"Skills更重要"——但这些判断对谁成立？
> 答案取决于你是**普通用户**、**应用软件开发者**、**产品经理**，还是**模型/Agent开发者**。

### 一句话概括

```
同一项技术，站在不同角色看，重要性完全不同：
- 用户觉得"不需要了"的东西，开发者可能正在大量使用
- 开发者觉得"有点用"的东西，模型厂商可能视为核心竞争力
```

### Prompt工程：真的"死了"吗？

| 角色 | 重要性 | 现实情况 |
|------|--------|---------|
| **普通用户** | ⬇️ 大幅降低 | 自然说话就行，不用背公式。"帮我写个邮件"就够了 |
| **应用软件开发者** | ➡️ 稍有降低 | System Prompt仍需精心设计；输出格式控制、边界约束都靠Prompt |
| **产品经理** | ➡️ 形式转变 | 不写Prompt了，但要定义Skills、设计Agent流程，本质还是"教AI做事" |
| **模型/Agent开发者** | ⬆️ 依然核心 | 推理链（CoT）设计、System Prompt架构、安全对齐——全是Prompt工程的进化形态 |

**洞察**：Prompt工程没有死，它**从用户侧下沉到了系统侧**。用户不再需要写复杂Prompt，是因为开发者和模型已经把这件事做好了。

### MCP协议：谁最需要它？

| 角色 | 重要性 | 现实情况 |
|------|--------|---------|
| **普通用户** | ⬇️ 几乎无感 | 不需要知道MCP是什么，只知道"AI能帮我查数据了" |
| **应用软件开发者** | ⬆️ 重要基础设施 | 接入第三方服务的标准方式；替代自研API封装，降低集成成本 |
| **产品经理** | ➡️ 能力边界 | 决定产品"能连什么"——有MCP就能接GitHub、Slack、数据库 |
| **模型/Agent开发者** | ⬆️⬆️ 生态关键 | 定义AI的"手脚"；MCP生态越丰富，模型能做的事越多 |

**洞察**：MCP的价值链是**自下而上**的——模型厂商定标准、开发者做集成、用户享受结果。用户看不见MCP，但每次"帮我查一下Jira"的背后都是MCP在工作。

### Agent Skills：谁受益最大？

| 角色 | 重要性 | 现实情况 |
|------|--------|---------|
| **普通用户** | ⬆️ 直接受益 | AI变得"更懂行"了：code review更专业、部署更规范，无需自己教 |
| **应用软件开发者** | ⬆️⬆️ 效率倍增 | 把团队最佳实践沉淀为Skill，新人即刻拥有老手经验 |
| **产品经理** | ⬆️⬆️ 差异化武器 | 自定义Skills = 产品护城河；竞品模型一样，但你的Agent更懂业务 |
| **模型/Agent开发者** | ⬆️ 架构补全 | 解决了"模型聪明但缺领域知识"的问题，降低对模型能力的过度依赖 |

**洞察**：Skills是**人人受益**的技术，但最大赢家是**应用开发者和产品经理**——它让"领域知识"变成了可安装、可复用、可版本化的资产。

### Agent自主性：该兴奋还是该担心？

| 角色 | 重要性 | 现实情况 |
|------|--------|---------|
| **普通用户** | 🎉 解放 + ⚠️ 信任 | "一句话搞定"很爽，但"它会不会搞砸"也是真实担忧 |
| **应用软件开发者** | ⚠️ 挑战 | 需要设计权限边界、回滚机制、审批流程——Agent越自主，安全架构越复杂 |
| **产品经理** | 🎯 核心机会 | Agent自主性 = 产品体验跃升，但需要平衡自动化与用户控制感 |
| **模型/Agent开发者** | 🔬 前沿课题 | 对齐、安全、可控性——Agent越强，这些问题越关键 |

### 总结：技术是同一个，视角决定判断

```
"Prompt工程已死"        → 对用户是真的，对系统开发者是假的
"MCP很重要"            → 对开发者是真的，对用户几乎无感
"Skills是最大创新"      → 对所有角色都是真的，但原因各不相同
"Agent自主性是未来"     → 对所有角色都是真的，但关注点完全不同
```

> 💡 **读者建议**：看待任何AI技术趋势时，先问自己："这个判断是对谁说的？"
> 同一个技术，用户侧的"不重要"往往意味着开发侧的"已经做好了"。

## 演进规律：多维度协同突破

**核心洞察**：
```typescript
// AI发展 ≠ 单一主线
// AI发展 = 多维度并行演进

{
  上下文: [4K → 100K → 1M → 2M],        // 记忆扩张
  交互: [手工 → 工程 → Agent],           // 易用性提升
  优化: [无 → Caching → Compact],        // 成本速度
  工具: [Function Call → MCP ⟂ Skills], // 能力+智慧
  推理: [无 → CoT → o1],                 // 思考能力
  协作: [单体 → 多Agent],                // 自主性
  部署: [云端 → 云本分化]                 // 新趋势
}

// 每个维度独立演进，在特定时刻交汇产生质变
```

**关键技术交汇点**：

| 时间 | 技术组合 | 产生效果 |
|------|---------|---------|
| **2023** | 长文本 ✕ Prompt工程 | 长文档应用爆发 |
| **2024** | 推理能力 ✕ MCP工具 | Agent萌芽 |
| **2025** | 百万token ✕ Skills ✕ 强推理 | **Agent时代** |
| **2026** | 多Agent ✕ 本地化 ✕ 协作 | 数字同事 |

## 💭 留给你的思考：AI时代的三个课题

在了解了AI从2022到2026的发展历程后，有三个问题值得我们每个人深入思考。

![课后思考题](/blog/images/after-class-questions.webp)

*图：像课堂上的课后作业，三个开放性问题等待你的答案*

### 课题1：For 企业与产品 🏢

**问题**：在AI能力爆炸的时代，如何在拥抱创新的同时保障数据安全？

**作者的思考**：
> MCP与Skills的广泛应用带来了前所未有的便利，但也带来了新的安全挑战：
> - **MCP连接外部服务**：如何确保第三方工具的可信度？
> - **Skills加载自定义知识**：如何防止敏感信息泄露？
> - **Agent自主执行**：如何建立安全边界，避免误操作？
>
> **我的答案**：安全不应该是创新的阻碍，而应该成为创新的护栏。
> - ✅ 建立Skills/MCP的审核机制（白名单、代码审查）
> - ✅ 实施分级权限管理（敏感数据隔离、最小权限原则）
> - ✅ 采用本地化部署（Clawdbot模式）处理关键场景
> - ✅ 建立监控和回滚机制（Agent行为可追溯、可撤销）
>
> 正如企业 AI 平台从早期成本教训到订阅制的演进，安全管理也需要在实践中不断完善。

**留给你的思考**：你的企业准备好平衡创新与安全了吗？有哪些具体措施？

---

### 课题2：For 个人成长 👤

**问题**：AI发展如此迅速，我们个人应该如何保持学习？以不变应万变，还是迎头赶上？

**作者的思考**：
> 回顾这3年：
> - 2023年学Prompt工程，2025年已经不需要了
> - 2024年学MCP开发，2025年Skills更重要
> - 2026年学的东西，2027年会不会又变了？
>
> **我的答案**：走马观花，但抓住本质。
>
> **❌ 不要做的**：
> - 追逐每个新技术的所有细节（会被信息淹没）
> - 每个新工具都深度学习（时间不够）
> - 因为变化太快就放弃学习（会被淘汰）
>
> **✅ 应该做的**：
> - 理解演进规律和底层逻辑（看清趋势）
> - 实践中学习，用AI帮助学习AI（降本增效）
> - 关注"不变的本质"（问题解决能力、创造价值的能力）
> - 建立快速学习新工具的能力（学习如何学习）
>
> **记住**：工具会变，但解决问题的能力不会过时。

**留给你的思考**：你打算如何在这个快速变化的时代保持竞争力？

### 课题3：For AI的未来 🔮

**问题**：AI发展如此迅猛，我们应该如何看待它的未来？

**作者的思考**：
> 历史告诉我们：
> - 从4K上下文的ChatGPT（2022）到1M上下文的Claude（2025），仅用3年
> - 从需要精心Prompt到自然对话，仅用4年
> - 从被动工具到自主Agent，我们刚刚开始
>
> **我的观察**：AI已经进入助理时代。
>
> 每个时代都不完美：
> - 2022：能对话，但记忆短（4K）
> - 2023：记忆长了（100K），但推理弱
> - 2024：有推理了（o1），但上下文还不够
> - 2025：全都有了，但成本高、速度慢
> - 2026：成本降低了，但新问题又来了
>
> **但规律是**：后一个时代总会解决前一个时代的问题。车轮滚滚向前，势不可挡。
>
> **我的信念**：
> - 短期会有波折（技术路线之争、安全问题、泡沫破裂）
> - 长期必然向前（AGI也许比我们想象的更近）
> - 与其恐惧，不如参与（我们都是这段历史的见证者和创造者）

**留给你的思考**：你对AI的未来是乐观还是谨慎？你准备如何参与这场变革？
